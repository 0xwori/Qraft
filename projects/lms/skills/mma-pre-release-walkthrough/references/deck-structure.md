# Pre-Release Walkthrough Deck Structure

Use this structure for Team MMA pre-release walkthrough and demo decks.

## 1. Title

Purpose:

- Show product, release or sprint, and Team MMA.

Typical content:

- `[Product] Pre-release walkthrough`
- `[Release / Sprint]`
- `Team MMA`

## 2. Purpose

Purpose:

- Explain what the walkthrough covers and what the audience should focus on.

Keep this short:

- What has been developed.
- What will be demonstrated.
- What still needs attention, if relevant.

## 3. Developed Work

Purpose:

- Give a clear overview of completed or nearly completed release work.

Default table:

| Jira key(s) | Theme / functionality | Platform | Status | Release / fixVersion | Demo relevance |
|---|---|---|---|---|---|
| `[KEYS]` | `[FEATURE]` | `[iOS / Android / Backend / Both]` | `[STATUS]` | `[VERSION]` | `[Demo / Mention / Background]` |

Rules:

- Group related tickets into one feature row when useful.
- Keep Jira keys visible.
- Do not overload the table; move detail to appendix if needed.
- Mark technical work as `Background` when it is not demo-friendly.

## 4. What We Are Going To Present

Purpose:

- Create a clean demo agenda.

Recommended format:

1. `[Demo step 1]`
2. `[Demo step 2]`
3. `[Demo step 3]`

Each step should map back to one or more rows in the developed work table.

## 5. Demo Time!

Purpose:

- Clear divider slide before the live demo.

Use a short, high-impact slide:

- `Demo time!`
- Optional subtitle: `[Product] - [Feature / flow]`

## 6. Optional Closing

Use only when helpful.

Possible content:

- Open points.
- Known risks.
- Follow-up actions.
- Next release or next sprint preview.
